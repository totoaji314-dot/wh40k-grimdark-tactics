## 0. Space Marine (2011) 원본 모델의 게임 적용 (로컬 전용)

사용자 지시에 따라 자체 마린 모델 제작을 중단하고, 추출된 **원본 메시·UV·노멀·스킨 가중치·텍스처를 그대로** 게임에 넣었다.
변환 스크립트는 저장소 밖 `SpaceMarine1_Extracted/_tools/sm1_unit.py`(Blender), 결과는 `SpaceMarine1_Extracted/_game_assets/units/`.

| 단계 | 방법 | 결과 |
|---|---|---|
| 메시 | `.smmesh` 파서로 원본 버텍스·삼각형·UV·노멀 그대로 생성 (축만 180° 회전: SM1은 +Y, 게임은 −Y를 정면으로 사용) | 레안드로스 10,470 / 시도누스 11,125 삼각형 (변경 없음) |
| BOD | `.bod` 장면 파일 형식 해석(`bod.mjs`: 문자열 해시 테이블 + 타입 태그 속성 트리, 5,519/5,519 바이트 완전 파싱) → 노드 위치·회전(오일러 XYZ, 도)·부모, 비주얼의 MeshID→노드 연결 | 볼터 9개 부품, 체인소드 본체+톱니, 견갑은 `RIG_*_ShoulderPad`, 백팩은 `RIG_SpineD`에 부착됨을 확인 |
| 무기 조립 | 볼터: 표준 부품 5개(본체·볼트·그립·조준기·부품)를 BOD 노드 변환으로 조립(XYZ 순서가 맞음을 렌더로 확인). 그립 기준점은 `RIG_Prop_LHand` 노드(측면 렌더로 권총 손잡이 위치 확인). 체인소드: 본체(오른손 소품 프레임)+톱니(월드 바인드)를 같은 프레임으로 정렬 | 볼터 길이 0.83 m, 총구 0.73 m 앞 |
| 리그 | 게임 리그(IK·무기 그립·총구 마커 포함)의 관절을 SM1 바인드 행렬에서 계산한 관절 위치로 이동(골반 1.225 m, 어깨 1.842 m, 무릎 0.746 m 등). 원본 스킨 가중치의 본 이름만 게임 본으로 매핑(RIG_Pelvis→hips, RIG_SpineD→chest, 손가락→hand 등). 견갑은 pauldron 추종 본(위팔 40% 추종), 백팩은 chest, 무기는 weapon 본에 강체 결합 | 37개 원본 스킨 본 → 게임 28개 본 |
| 텍스처 | 2048² 아틀라스 칸에 원본 DDS 픽셀을 1:1 복사(재샘플 없음). 원본 UV는 [1,2]·[−1,0] 타일 좌표라 면 단위로 [0,1)로 감싼 뒤 칸으로 이동. 노멀맵은 DirectX→OpenGL(G 반전), ORM은 스펙 맵에서 거칠기·금속도 추정, 헬멧 눈은 발광 | 텍스처 원본 유지 |
| 애니메이션 | 게임 애니메이션 생성기(`anims.py`)를 SM1 크기 몸체(보폭 ×1.2)로 실행 | 24개 클립 (아래 3절) |
| 변환 | 게임과 같은 GLB 계약(LOD 3단계, PLACEHOLDER 재질, 클립 메타 JSON) + meshopt 압축 | 4종 6.2 MB |

적용 병종:

| 게임 병종 | SM1 몸체 | 무기 |
|---|---|---|
| 전술 마린 | 레안드로스 | **SM1 볼터** |
| 플라즈마 마린 | 레안드로스 | 게임 기존 플라즈마 건 (SM1 데모에 없음) |
| 헤비 볼터 마린 | 레안드로스 | 게임 기존 헤비 볼터 (SM1 데모에 없음) |

- 게임 연결: Vite 개발 서버 전용 경로 `/local-assets/`가 저장소 밖 폴더를 제공하고, 게임·뷰어가 이 파일이 있으면 마린을 SM1 모델로 불러온다(`?sm1=0`이면 끔). `vite build`/GitHub Pages에는 포함되지 않음을 빌드 결과물 검색으로 확인했다.

- 색 보정: SM1 디퓨즈는 때가 많이 구워져 어두워서, 게임 실행 시 재질 색 ×1.35·환경 반사 ×1.6을 적용(텍스처 파일은 그대로).

### 남은 문제
- 손가락 본이 손 본에 합쳐져 손가락이 굽혀지지 않는다(원본 손 모양 그대로 무기에 붙음).
- 시네마틱/인게임 얼굴 메시(`cinematic_*`, `ingame_*`)는 BOD 노드 좌표계(z≈4.1 m)를 아직 적용하지 않아 조립하지 않았다(헬멧을 쓴 상태라 게임에는 보이지 않음).
- Havok 원본 애니메이션 702개는 스플라인 압축 해제기를 아직 만들지 않아 쓰지 못했다. 현재 애니메이션은 게임 생성기로 만든 것이다.
- 벨트 천(cloth) 부품은 Havok 천 시뮬레이션용이라 제외했다.

비교 렌더(비공개 폴더 `SpaceMarine1_Extracted/_analysis/renders`)로 확인한 기존 모델의 결함과 이번 수정:

- 몸 비율: 견갑 폭/키 비율 0.58 (SM1 측정값 0.585).

### 남은 차이 (정직한 평가)
- SM1은 손으로 조각·도색한 노멀/디퓨즈 맵으로 아퀼라·패널·마모를 표현한다. 이 모델은 절차적 재질(모서리 마모·긁힘·때)과 기하 디테일이라, **근거리에서 텍스처 디테일은 SM1에 못 미친다**. 표면이 매끈하고 장난감 같은 느낌이 남아 있다.
- 견갑의 챕터 상징/분대 표식 배치가 공식 관습(서로 반대쪽 견갑)과 정확히 일치하지 않는다.
- 다음 단계: 하이폴리 디테일(패널 라인·리벳·아퀼라 깃털)을 별도 메시로 만들어 노멀맵에 굽기, 데칼 아틀라스.

## 3. 애니메이션 현황
- 진영 공통 **24개 클립**, Blender에서 IK(발 고정·손 무기 고정)로 프레임마다 키를 찍어 생성. 크로스페이드는 `src/sim/anim.ts`.
  - 기존 17: 대기·경계 조준·걷기·조준하며 걷기·달리기·돌격·제자리 회전·사격(반동)·재장전·근접 A/B·가벼운 피격·사망 A(뒤로)/B(앞으로)·엄폐·엄폐 사격·지휘
  - 이번 추가 7: **방어(block)**·**경직(stagger)**·**넘어짐(knockdown)**·**일어나기(getup)**·**측면 사망(death_c)**·**강공격(melee_c)**·**전력질주(sprint)**
- 전투 연결(`src/sim/Battle.ts`): 빗나간 공격은 상대가 막는 동작, 최대 체력 35% 이상 피해는 경직, 질량 2배 이상 돌격은 넘어뜨림 → 낙하가 끝나면 일어나기(그동안 이동·공격 불가), 장교·보스·중량 병사의 강공격(피해 ×1.35), 사망 방향(정면 피격 → 뒤로, 후방 → 앞으로, 측면 → 옆으로), 패주 시 전력질주.
- **미구현**: 후진/측면 이동, 회피 구르기, 상하체 분리 레이어, 조준 오프셋, 절차적 반동 셰이더, 손가락 쥐기. 요청 목록 37–50종 중 24종에 실제 키프레임이 있다.
